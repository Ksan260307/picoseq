# PicoSeq — レトロピコピコ・シーケンサー v2

チップチューン（ファミコン風）の作曲アプリ。単一 HTML だった旧版
（`../main.html`）を、**確定核と観測層を分離した Python アプリ**として作り直したもの。

- マス目に音を置いてフレーズを作り、フレーズを並べて曲を組み立てる
- 4 パート（メロディ / ベース / リズム / サブ）を重ねられる
- キー・曲調・シードを選んで **ワンボタン自動作曲**
- **自動伴奏**: メロディだけ描くと、その旋律に合うベース・リズム・サブを自動生成
- **フォト和音**: カメラで撮った写真から四角形を抽出し、その形から音階とコード進行を生成
- **リアルタイム反映**: 演奏を止めずに音を足したり消したりすると、その場で演奏へ反映
- ❓ ヘルプ画面（F1）で使い方をいつでも確認
- 音は **整数演算だけで合成**するので、同じ入力からは常に同じ WAV が出る
- 標準ライブラリ（tkinter / winsound）だけで動く。**追加インストール不要**
  （numpy があれば合成が速くなる／JPEG 写真は Pillow があれば対応。PNG / BMP / PPM は純 Python で復号）

## 動かし方

Python 3.9 以上（Windows 想定。tkinter 同梱の標準 CPython）。

```console
cd picoseq
py main.py            # GUI を起動
py main.py --selftest # 画面を出さずに配線を自己診断（終了コード 0 = 正常）
py main.py --demo     # デモ曲を読み込んだ状態で起動
```

音の再生は Windows の `winsound` を使う。他 OS では GUI と WAV 書き出しは
動くが、その場での試聴は無音になる（`SoundPlayer(silent=True)` 相当）。

## 使い方

**フレーズ作成タブ**

- グリッドを**左クリックで音を置く**。置いたまま**右へドラッグで音を伸ばす**
- 音符を**クリック**、または**右クリック**で消す
- 左端の**鍵盤をクリックで試聴**
- 「パート」ボタン（またはキー `1`〜`4`）で編集対象を切り替え。選択中のパートが明るく表示される
- 「音色」「長さ」スライダーでパートごとの音作り
- **キー・曲調・シード**を選んで「✨ 自動作成」でフレーズを生成。「🎲 おまかせ」はシードをランダムに選ぶ
- **「🎸 伴奏づけ」**: メロディ（パート1）だけを描いた状態で押すと、その旋律に合う伴奏を自動生成（下記）
- 「★ 登録」で現在のフレーズをパターン（最大 8 個）として保存

**自動伴奏（🎸 伴奏づけ）**

メロディだけを盤面に置いて押すと、ベース・リズム・サブが自動で付きます。仕組み:

1. メロディを半小節ごとの窓に分ける
2. 各窓で、スケール各度数のコードにメロディ音がどれだけ乗るかを長さで重み付けして採点し、最も合う度数を選ぶ → **コード進行を推定**
3. 推定した進行で伴奏 3 パートを決定論的に生成し、メロディに重ねる

推定した進行はプロジェクトに記録されるので、以後の再現・再生成でも同じ和音が使われます。
曲調やシードを変えてから押すと、同じメロディでも違う雰囲気の伴奏になります。

**再生とリアルタイム反映**

「▶ 再生」でループ再生。**演奏中に音符を足す・消す・伸ばす、テンポを変えると、止めずにその場で反映されます**
（現在の再生位置から途切れずに続きます）。合成は音声キャッシュ＋（あれば）numpy で高速化しているため、
編集のたびに素早く鳴り直します。

**フォト和音（📷 写真から）**

1. フレーズタブの「📷 写真から」で写真を選ぶ（紙・カード・本・画面など、四角い被写体を背景と明暗差をつけて撮る）
2. 検出した四角形がプレビューに重ね描きされ、生成される **キー・曲調・テンポ・コード進行** が表示される
3. 「♪ この和音で作曲」で適用（1 回のアンドゥで戻せる）

写真の形は次の規則で音楽に写像される（すべて決定論。同じ写真 → 同じ曲）:

| 写真の特徴 | 音楽への写像 |
| --- | --- |
| 四角形の中心の **x 位置** | キー（左 = C 〜 右 = B の 12 分割） |
| **整形度**（4 隅の 90° からのズレ） | 曲調: 整うほど明るく、歪むほど激しい（major → minor → japanese → battle） |
| 各コーナーの **角度のズレ**（TL→TR→BR→BL） | コード進行: スケール既定進行を 15° につき 1 度ずらす（正方形 = 既定進行そのもの） |
| 画面に占める **面積比** | テンポ（大きく写すほど速い） |
| **コーナー座標**のハッシュ | シード（同じ写真からは同じ曲が生まれる） |

解析結果はプロジェクトに確定入力として記録されるため、保存すれば写真なしでも同じ曲を再現できる。
CLI でも確認できる: `py -m picoseq.vision 写真.jpg`

**ソング作成タブ**

- 上のパレットでパターンを選び、下のグリッド（4 トラック × 16 ブロック）に配置
- 横に並べれば連結、縦に並べれば重ねて再生
- 「🎵 WAV書出」で曲全体を `.wav` に書き出し

**共通**

- `Space` 再生 / 停止、`Esc` 停止、`Ctrl+Z` / `Ctrl+Y` 元に戻す / やり直す、`Ctrl+Tab` タブ切替
- 「💾 保存 / 📂 読込」は `~/.picoseq/autosave.json` に自動保存。「⬇ 書出 / ⬆ 取込」は任意の場所へ
- **旧版（main.html）の `retro_project.json` もそのまま取り込める**

## 設計 — UCD-F 準拠

このリポジトリの [`CLAUDE.md`](../../../CLAUDE.md) / Universal Core の層分離に沿って、
**確定状態を決める核**と、**状態に触れない観測層**を分けている。

```
picoseq/
├── main.py                起動スクリプト（--selftest / --demo）
├── picoseq/
│   ├── core/              確定核 — 純粋関数のみ。I/O・描画・実時間なし
│   │   ├── constants.py   論理スキーマの限界値・パート定義
│   │   ├── prng.py        決定論 PRNG（mulberry32、整数演算）
│   │   ├── music.py       キー / スケール / コード / 周波数テーブル
│   │   ├── note.py        音符の 32bit ビットパック（旧版と同一レイアウト）
│   │   ├── phrase.py      フレーズバッファ操作（不変タプル）
│   │   ├── song.py        ソンググリッド操作
│   │   ├── project.py     確定状態 S 全体（frozen dataclass）
│   │   ├── actions.py     状態遷移 C_D（すべて純粋関数）
│   │   ├── composer.py    シード付き自動作曲・伴奏生成
│   │   ├── arranger.py    メロディからコード進行を推定して伴奏を付ける
│   │   ├── schedule.py    Tick→サンプルの時刻計算・イベント展開
│   │   ├── synth.py       固定小数点シンセ（位相=32bit / 音量=Q15 / LFSRノイズ）
│   │   ├── renderer.py    イベント→PCM のミックス（整数加算＝順序独立／音声キャッシュ・numpy 経路）
│   │   ├── wavio.py       WAV 符号化
│   │   ├── serialize.py   版付き JSON の入出力・旧版データ移行 (schema v2)
│   │   └── history.py     アンドゥ / リドゥ
│   ├── vision/            フォト和音 — 入力の権威化 (写真 → 確定入力)
│   │   ├── image.py       画像復号 (PNG/BMP/PPM 純 Python) と縮小グレースケール化
│   │   ├── quad.py        四角形検出 (Otsu → 連結成分 → 凸包 → 最大四角形)
│   │   ├── harmony.py     四角形 → キー・音階・進行・テンポ・シードの写像
│   │   └── __main__.py    CLI (py -m picoseq.vision 写真)
│   └── ui/                観測層 — 表示と入力。core 経由でのみ状態を変える
│       ├── theme.py       配色・フォント
│       ├── roll_view.py   ピアノロール
│       ├── song_view.py   ソンググリッド
│       ├── photo.py       フォト和音ダイアログ
│       ├── help.py        ヘルプ画面
│       ├── playback.py    winsound 再生・再生時計・PCM 回転（途中から再生）
│       ├── storage.py     ファイル置き場
│       └── app.py         画面の組み立て・配線・リアルタイム再レンダリング
└── tests/                 テストスイート（unittest）
```

### 守っている不変条件

| 原則 | 実装 |
| --- | --- |
| **決定論・再現性** | 乱数は `prng.py` の明示シードのみ。同一 `(拍子,キー,曲調,シード)` → 同一フレーズ |
| **順序独立性** | ミックスは整数加算（結合律・交換律）。イベント順を変えてもビット等価 |
| **実装間ビット等価** | 音声合成は固定小数点。浮動小数点 `atomicAdd` 相当の非結合演算を使わない |
| **適応の 2 分類** | 状態変更は確定状態・権威化入力のみ。再生位置の表示だけ実時間（`PlayClock`）を使い、状態には反映しない |
| **可逆性** | アンドゥは直列化スナップショット。保存＝プロジェクト全体（＝再生同一性 + 入力） |
| **版検査** | 保存データはアプリ ID とスキーマ版を持ち、他アプリ / 新しすぎる版の読込を拒否 |
| **データ指向** | 音符は論理スキーマ（ビットパック）。物理表現はプロファイル裁量 |

観測者カメラ（スクロール位置・再生ヘッド）は確定状態に一切影響しない。
これは「適応分離検証」（入力列を固定して表示だけ変えても状態列が不変）に対応する。

## テスト

```console
cd picoseq
py -m unittest              # 全テスト
py -m unittest -v           # 詳細表示
py -m unittest tests.test_composer   # 個別
py run_tests.py             # 上と同じ（まとめ実行）
```

| `test_composer` | 自動作曲の決定論・音楽的不変条件 | 再現性 |
| `test_arranger` | メロディ検出・進行推定・伴奏生成の決定論と整合 | 再現性 |
